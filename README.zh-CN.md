AI 越来越多：这家一个 app，那家一个 app，同一家隔几个月又换个新地方，每换一次你都得搬一次家。

Aelios-resident 是一个家，你的每一个 AI 都是住在里面的住户。家在**你自己的 Cloudflare 账号**里，一天二十四小时都在。每个住户用它自己的模型，有它自己的名字、样子、脾气和记忆，谁也不顶替谁。网页上、Telegram 上、微信里，你在哪儿找它，都是同一段对话。它记得你上个月说过的事；你太久没动静，它会来问一句；交代给它的活，它交给后台去做，做完了再来告诉你。

不用租服务器，也不用会写代码：把一段话发给会装软件的 AI，十来分钟后就能跟它说上话。Cloudflare 的免费档就够它住。**[现在就让它住进来 →](#上线)**

## 它是怎样的

### 它记得你

- 接上 [Aelios](https://github.com/wusaki0723/Aelios)（你自己部署的记忆服务）后，你每说一句，它都会想起相关的旧事，再把这一轮记下来。几个月前你提过的猫叫什么，你在为什么努力，你不爱吃什么，它都知道。
- 聊久了，它给之后的自己写交接信，把旧聊天收好，只留最近一段原文。第二天接着聊，话头不断。
- 每个住户的记忆是它自己的：接了 Aelios 时，一个住户一个身份，各记各的。

### 它会来找你

- 到你定的时间，它想想要不要跟你说句话；你一阵子没动静，它会问问自己要不要来找你。夜里不打扰，除非你愿意。
- 它能自己定闹钟，到点回来找你。
- 网页门能装到手机主屏幕上。它来找你、线程做完、闹钟响了，都会推送通知给你。

### 它有声音，也有表情

- 你发的图它看得懂，你发的语音它听得懂。它也能开口回你：ElevenLabs、Cartesia，或经 OpenRouter 用 MiniMax、Gemini 等的声音，你克隆的声音也行。
- 它会发表情包：导入一个 Telegram 贴纸包就行，它还会自己画像素小表情。
- 人设由你来写：它叫什么、怎么说话、是个什么样的人，都由你决定。

### 它能替你做事

- 它会搜网、读网页；给私有网站存一把钥匙，那些页面它也读得了。
- 大一点的活，比如查一堆资料、写报告、做网页、改代码，它交给后台线程，自己接着陪你聊。做完了，它用自己的话告诉你，做出来的文件在网页上就能看、能下载。它也能把活交给 GitHub Actions 或云端 Claude Code。
- 线程不用你管。说一句「接着上周那个网页做」「那份资料查到什么了」，它自己去找那条线程、它做的文件或者当时说过的话。
- 跑腿用便宜的模型：后台线程默认用免费的模型，也能换成 DeepSeek 这类别的模型，陪你聊的那个的额度不花在跑腿上。
- 再接上别的 MCP 工具，它会的就更多。

### 它只属于你

- 它住在你自己的 Cloudflare 账号里：对话、人设、表情包、线程做出来的文件都存在那儿，不在作者或任何平台手上。
- Cloudflare 免费档就能跑，默认模型也免费。想用 Claude 这类模型，再按用量付模型的钱；每一次调用花了多少，「用量」里一笔一笔看得到。
- 开源，AGPL-3.0。

## 上线

### 让 AI 帮你装（推荐）

用 Claude Code、Codex 这类能跑命令的 AI 的话，把下面这段话发给它。部署、接 Aelios（要 Telegram 的话也接上）、选模型都交给它，你只要在浏览器里点几下；要 Telegram 的再建个 bot：

```text
帮我装好、配好 Aelios-resident（住在我 Cloudflare 账号里的 AI 伴侣）。先读 https://raw.githubusercontent.com/wusaki0723/Aelios-resident/main/docs/setup-with-ai.md ，照着做。需要我在浏览器里点、或者需要我自己填 key 的时候，停下来告诉我去哪儿填。
```

### 自己在后台点着装

要准备：一个 Cloudflare 账号（免费档就行）。想要长期记忆的话，再准备一个已经部署好的 Aelios。Telegram 和企业微信都是选装的，都在设置页里接：不要 Telegram 就跳过第 1 步；企业微信装好以后再接，见「企业微信」。

1. **建 bot**（只有 Telegram 要）：在 Telegram 里找 @BotFather，发 `/newbot`，起好名字，记下 token。
2. **部署**：Cloudflare 后台 → Workers & Pages → Create → Import a repository，选这个仓库（或者你 fork 的）。项目名填 `aelios-resident`，要跟 `wrangler.jsonc` 里的 `name` 一样，其余用默认。以后推到 main 就自动更新。
3. **填 Secret**：Worker → Settings → Variables and Secrets。只有 `WEB_KEY` 在这里填，别的（连 bot token 在内）都在网页上填。
   - `WEB_KEY`：网页门的钥匙，自己编一串长的。拿到它的人能看全部对话、改所有设置，别截图、别外发；怀疑漏了就在这里换一个。不填的话，普通浏览器进不去，只能从 Telegram 的 Mini App 进。
4. **在网页上填设置**：打开 `https://aelios-resident.<你的子域>.workers.dev/`，填 `WEB_KEY` 进门，点右上角的「···」（设置）：
   - 接了 Telegram 的：「聊天渠道」→「接 Telegram」→「bot token」：贴上第 1 步的 token，保存。住户会先找 Telegram 核对，再自己接好：webhook、三个命令，还有 bot 左下角打开网页的菜单按钮。再填下一步「谁能在 Telegram 上跟它说话」：你的 Telegram 用户名，比如 `@your_name`。不填的话它在 Telegram 上谁都不回。两步都好了，Telegram 那张卡写着 bot 的名字和「已连」。
   - 「长期记忆」：填 Aelios 的地址和 key。key 跟你 Aelios 那边的 `CHATBOX_API_KEY`、`IM_API_KEY`、`MEMORY_MCP_API_KEY` 任意一把相同即可。再到 Aelios 后台给住户建一个身份，把要用的模型放进这个身份的主模型；身份名填在「更多设置」→「身份」里（不填就用这把 key 的第一个身份）。
   - 回到聊天：点顶上名字下面那一行选模型；点左上角它的头像，再点「人设」卡上的小笔，贴上人设、保存。
5. 在网页门说一句，或者给 bot 发条消息试试。

以前装的、`TG_BOT_TOKEN` 和 `TG_WEBHOOK_SECRET` 放在 Cloudflare 里的：照样能用，`/tg/setup?secret=<TG_WEBHOOK_SECRET>` 也照样能接。设置页存了 token 的话，用设置页的。

## 怎么运作

整个住户就是一个 Cloudflare Worker 加一个 Durable Object，基于 Cloudflare 的 [Think](https://developers.cloudflare.com/agents/)。

- **不用租服务器**：免费档就能跑。
- **不用另建数据库**：聊天记录、交接信、人设、表情包都存在 Durable Object 自带的 SQLite 里。
- **都在网页上改**：部署好以后，模型、人设和所有设置都在网页上点，改完下一句就生效。

```
网页门 / Mini App ──────────────▶ Worker /web/* ──┐
Telegram（选装）──▶ Worker（验 secret、白名单、命令）──┤
企业微信（选装）──▶ Worker（验签名、解密、白名单）──┤
                                                ▼
                    Resident（一个 Durable Object，一段对话）
       人设 + 聊天规矩 + Aelios 开机包
       工具：记忆、搜网、读网页、表情包、语音、闹钟、别的 MCP、云端 Claude Code
                                                │
             回企业微信的消息 ──▶ 有固定 IP 的转发机 ──▶ 企业微信接口
```

- 接了 Aelios 时，每一轮都经过 Aelios 的模型接口，由它补上相关的旧事并记下这一轮。
- 企业微信只认固定 IP 发来的接口调用，所以回企业微信的消息要经过你自己一台机器上的小转发机（见「企业微信」）。Telegram 和网页门不用别的东西。
- 你停下来 55 分钟后：聊天够长就写交接信；还不够长就走心跳，问它要不要找你。

## 用起来

### 网页门

打开 Worker 的网址，填 `WEB_KEY` 进门。它跟 Telegram、企业微信是同一段对话：那边说的话 5 秒内出现在这里；在网页上说的话只在网页上回，不发到别的门。页面上的按钮都是小图标，鼠标放上去或手机上长按能看到名字（下面「」里写的就是）。

- **说话**：打字，或者点「＋」：发图（一次最多 4 张，相册或拍照）、写交接信、换模型；输入框里的小笑脸发表情包。按住话筒录语音条（最长一分钟），跟 Telegram 上的一样先听成文字。
- **长按**一条消息（电脑上点右键）：引用着回它、复制、存进 Aelios 的「珍贵」，设了声音的话还能「念给我听」。
- **收回它最后一条回复**：它最后一条回复说完以后，长按它（电脑上点右键），菜单里多两项：「重新生成」是删掉再回一遍，「删掉」就是删掉。别的消息的菜单里没有这两项。回复报错、token 点歪成乱码、或者突然一句干巴巴的「我不能完成这个任务」，点一下，这条就从对话里拿掉，它以后看不到。只能收回最后一条，前面的都不动，缓存照样命中。接了 Aelios 的话，Aelios 那边还记着一份原话：去 Aelios 后台首页「今天的对话」里把那句删掉。
- **搜聊天记录**：顶上的放大镜，搜你和它说过的所有话（哪扇门说的都算），新的在前，被交接信收起来的旧聊天也搜得到。点一条看前后几句；还在聊天里的，点「在聊天里看」跳过去。按你打的字原样找（英文不分大小写），最多 50 个字，最远往回 1 万条（跟对话本身读得到的一样）。
- **它干了什么**：想的和用过的工具，在它回复下面收成一行虚线，比如「想了一下 · 忙活了 2 回」。点开看每一步，再点一步看完整的参数和结果。
- **卡片**：它读过的网页、定的闹钟（能在卡上改时间、删掉），在那条回复下面。交给线程的活是一张小卡片，只挂在最新提到它的那条回复下面（先是派活那条，交回来以后是交回来那条）：标题、状态、两行报告和进线程的按钮，完整的报告和链接在线程里。线程要你拍板时，卡上直接给几个按钮选。
- **Markdown**：它的回复、线程交回的报告、线程里的 `.md` 文件，按 Markdown 显示粗体、列表、表格、代码和链接。里面的东西从不当 HTML 读，链接只开 http(s) 的地址。
- 它没被问就发的话，上面标着「主动找你」；换了模型，聊天里有一行写着；交接信折叠显示在它收起聊天的位置。每条消息有时间，不是在网页上说的还写着从哪扇门来。
- **它的页面**：点左上角它的头像，换头像和名字、换模型、改人设，看记忆、闹钟、线程和用量。
- 夜间、白天两种样式，或者跟着系统（在设置页最下面选）。手机上也好按。

**当成 App、收通知**：在手机上把网页门加到主屏幕（Safari：分享 →「添加到主屏幕」；Chrome：「安装应用」），再从聊天里那张卡，或设置页「通知」里打开通知。默认（`WEB_PUSH`）它主动找你、线程做完、闹钟响了，这些话没发到 Telegram 或企业微信的推过来；你在网页上说了话走开 20 秒以上，它的回复也推过来。iPhone 和 iPad 只有从主屏幕图标打开才能收（iOS 16.4 起）；Telegram 的 Mini App 里没有通知。签通知用的钥匙是第一个住户自己生成的，只存在它身上，开了通知的设备名单也存在它那里；别的住户用同一把钥匙签、推给同一份名单。

### Telegram

- 只回私聊，只回「谁能在 Telegram 上跟它说话」里的人。
- 连着发几条，它会等 3 秒、并成一轮再回（`DEBOUNCE_SECONDS`）。
- 回复按空行拆成几条，写完一段发一段，中间显示「正在输入」。
- 每条消息前面带着你那边的时间，它知道现在几点。
- 你发的图它看得到（照片，或当文件发的图，20 MB 以内）。有 Cloudflare Images 时（`wrangler.jsonc` 里的 `IMAGES` 绑定，每月 5000 张以内免费），长边超过 1568 像素的图先缩到 1568 再发给模型，模型本来也是按这个大小看的。没有 Images 时图原样发，3.75 MB 以内（编码后 5 MB，Claude 一张图的上限）。

**Mini App**：点 bot 左下角的菜单按钮，网页门直接在 Telegram 里打开，不用填 `WEB_KEY`。它凭 Telegram 签过名的身份进门，每次都按「谁能在 Telegram 上跟它说话」重新查一遍，把人从名单里拿掉就进不来了。换了自定义域名的话，从新域名打开设置页，在「聊天渠道」的 Telegram 卡上点「重新接一次」（Telegram 只开 https 的 Mini App）。细节见 `src/mini-app.ts`。

**命令**：

| 命令 | 做什么 |
| --- | --- |
| `/status` | 现在用的模型、人设、对话多长、写过几封交接信、上一轮缓存读了多少、表情包和语音的状态 |
| `/letter` | 看最近一封交接信 |
| `/handoff` | 现在就写一封交接信，不受 token 门槛限制，但要有旧内容可收（见「交接信」） |

### 企业微信

选装。企业微信是腾讯的办公聊天软件，自己建一个免费的小企业就够；开了「微信插件」，同一个聊天在普通微信里也能收发。住户用这个企业里的一个「自建应用」跟你聊。

企业微信只接受应用「企业可信 IP」发来的接口调用，而 Worker 没有固定 IP。所以住户回你的消息要经过你自己一台有固定 IP 的 Linux 机器（比如 VPS）上的小转发机。转发机不开端口：只听 `127.0.0.1`，经 Cloudflare Tunnel 出来。企业微信推给住户的消息直接到 Worker，不经过它。转发机和怎么装，见 [relay/wecom](relay/wecom/README.md)。

**按这个顺序装**：

1. **转发机**：在那台机器上跑 `sudo relay/wecom/install.sh`（要语音条加 `--media`，会装 ffmpeg），再用 Cloudflare Tunnel 给它一个网址，指到 `http://127.0.0.1:8787`。细节见 [relay/wecom](relay/wecom/README.md)。
2. **建应用**：企业微信管理后台（work.weixin.qq.com）→「应用管理」→「创建应用」。「可见范围」里要有你自己。
3. **设置页 →「聊天渠道」→「接企业微信」**，一步一步填：「企业 ID」（「我的企业」页面最下面）和应用的 AgentId、Secret；转发地址和转发钥匙；下面第 4 步做完后，再填「谁能在企业微信上跟它说话」（你在通讯录里的「账号」）。每项填完点保存。
4. **接收消息**：应用页「接收消息」→「设置 API 接收」。URL 填设置页「接收消息」那一步写的那个（`https://<住户地址>/messengers/wecom/webhook`）；Token 和 EncodingAESKey 都点「随机获取」，**先复制到住户设置页存好**，再回企业微信点保存。企业微信保存时会来验一次地址，住户要有这两样才答得上。
5. **可信 IP**：同一个应用页，「企业可信 IP」填转发机出去时的 IP（在那台机器上 `curl -s https://ifconfig.me`）。企业微信要先设好接收消息的 URL 才让填。
6. 在企业微信里给它发一句。想在微信里聊：「我的企业」→「微信插件」，用微信扫邀请关注的二维码，之后微信里就能跟这个应用聊。

`/status` 的「企业微信」一行和设置页「聊天渠道」里的企业微信卡，会写着还差什么、转发机连不连得上、能不能发语音。

**能做的**：

- 文字来回；你发的图片；装了 `--media` 后语音条来回都行。没装的话，它的语音回复改成文字，你发的语音它可能听不了。
- 表情包要在「聊天渠道」的企业微信卡上打开「在企业微信上发表情包」（默认关），发出去是静图。企业微信没有表情包这一类消息，只能发图片，它不放动图，还会把透明底变成黑底。所以动图挑最完整的那一帧转成 PNG，透明的地方垫上「表情包垫的底色」（默认 `#EDEDED`，微信浅色模式的聊天背景，看着就像贴在聊天里；深色模式选「深色模式」，也能自己填颜色），小图放大一倍、像素照样清楚。PNG 表情一样垫底，JPG 直接发，Telegram 包里的 WebP、WebM 要转发机装了 `--media`。关着时它发的表情包在这里不发，网页和 Telegram 上照常显示。
- `/status`、`/letter`、`/handoff`，跟 Telegram 一样。
- 定时找你、心跳、闹钟、云端干完活的回报，都发到你最后说话的那扇门：最后在企业微信说的话，就发到企业微信。

**限制**：企业微信只显示纯文字，Markdown 会去掉（链接变成文字加网址）；超过 2048 字节的回复会拆开；没有「正在输入」；语音条最长 60 秒；企业微信每分钟给同一个人最多发 30 条左右；表情包不会动。

### 好几个住户

一个 Worker 上可以住好几个住户，各有各的人设、模型、设置、聊天、表情包、闹钟和 Telegram bot。网页门左边一列是它们的头像（手机上点左上角的 ☰），点谁就切到谁；最下面的「＋」建一个新的，填名字和代号（小写英文，比如 `mochi`）。别的住户刚说过话，它的头像上亮一个小点。

- **第一个住户**还是原来的样子，网址、设置、bot 都不变。不建新住户就什么都不用管。
- **新住户的地址**都在 `/r/<代号>` 下面：网页是 `/?r=<代号>`；Telegram webhook、企业微信的「接收消息」、线程回报、MCP 授权回来的地址都带这一段，住户自己填好，不用你算。
- **记忆**：Aelios 的地址和 key 跟第一个住户共用，身份默认就是它的代号（走 `/<代号>/`），记忆空间跟着身份走。在 Aelios 后台建好这个身份、配好主模型就行；想换身份，在它的设置页「长期记忆」里改。key 要用 Aelios 的主密钥 `CHATBOX_API_KEY`：别的 key 只能读写 default 空间，两个住户的记忆会串到一起。
- **只认它自己的设置**：Telegram bot token、企业微信应用（AgentId、Secret、Token、EncodingAESKey）、claude.ai 定时任务的触发网址和 token、Aelios 身份和空间、名字、主动找你和心跳（新住户默认不主动问，要的话自己开）。这几项 Cloudflare 里的变量只给第一个住户用。其余的（供应商、Claude 盒子、搜网、声音、GitHub token、时区、谁能跟它说话）没填就跟 Cloudflare 里的一样。
- **自己的 bot**：找 @BotFather 再建一个 bot，在新住户的设置页「聊天渠道 → Telegram」贴它的 token，它会自己接到 `/r/<代号>` 上，菜单按钮打开的 Mini App 也是它。企业微信要另建一个应用，「接收消息」的网址照它设置页上写的填。
- **通知**：整个网页门一把签名钥匙、一份设备名单。在哪个住户的页面上开一次通知，哪个住户都能推过来，点开就是那个住户；在任何一页关掉，就全关了。
- **删掉**：点头像进它的页面，最下面「删除这个住户」，输入代号确认。它的聊天、设置、表情包、闹钟都删掉，bot 也放开；Aelios 里的记忆不动。它马上从列表里消失，但删干净之前代号一直占着，不能拿来建新的；没删干净的过几分钟会自己再删一次。第一个住户删不掉。除了第一个，最多再建 8 个。

**群聊**：有两个以上的住户时，左边头像下面多一个「新群聊」。群可以建好几个（最多 20 个），每个群勾上要进群的住户，起个名字（不填就用成员的名字），左边一个群一个图标。群聊只在网页门上，Mini App、Telegram 和企业微信上没有。

- **谁回**：你说一句，群里的住户按左边的顺序回，后说的听得见先说的。`@` 谁就只叫谁；点输入框上面的头像，就把它的 `@` 填进去。住户之间不互相 `@`；大家都说过一遍以后，有新话可听的再轮一遍，你的一句话最多聊 3 轮（设置里 1 到 5）。每次都告诉它这是第几轮、可以回 SKIP 结束；一轮里谁都没说话就停。
- **跟私聊一样**：一条回复分几段就是几个气泡，按 Markdown 显示。能发图（一次最多 4 张），能发表情包（用你进群前所在那个住户的表情包）；住户发的表情包也显示。图片跟着话一起交给每个成员，表情包它按意思读。发文件和私聊一样还不行。
- **进各自的对话**：轮到哪个住户，群里它上次说话之后的话就整段交进它自己的对话（每行前面写明是谁说的），它在那里回，用自己的人设、模型、工具和记忆，回的话再贴回群里。所以它知道群里聊了什么，Aelios 照常给它回忆、照常记下来，之后私聊也能接着说。群里的话只显示在群聊页面上，不出现在私聊页面里，也不另推通知到手机。一次最多交给它最近 60 条它没听过的。
- **停下**：顶上的方块按钮让还没回的都不回了，也不再开新的一轮。正在回的那个会说完，反正它那句已经在它自己的对话里了。
- **设置**（顶上的滑杆图标）：图标（点一下换图，和头像一样谁拿到地址都能看）、群名、群里有谁、没 `@` 人时谁回（大家都回、一个人轮着回、都不回）、谁先说（按左边的顺序、每次打乱）、最多聊几轮，还有「删掉这个群」。删群会删掉群里的话、图片和图标，成员各自对话里听到的还在。
- 群和群里的话存在第一个住户那里；每个住户的用量时间流里，群聊那几轮写着「群聊」。

## 功能细节

### 长期记忆（Aelios）

接了 Aelios 以后，聊天从 Aelios 自己的模型接口过（`https://<Aelios>/<身份>/v1`），跟别的聊天软件接 Aelios 一样：

- Aelios 拿你这句话想起相关的旧事，贴在这句后面给模型看，再把这一轮记下来。想起的旧事只在那一轮看得见。
- Claude 走 Messages 接口，缓存标记放在你那句上，之前的聊天照样从缓存读。
- 模型另有 7 个记忆工具：查、记一句、存珍贵瞬间、归档、记黑话、翻日记，还有小本本。小本本是 Aelios 里按页名读写的笔记，适合记学习进度这类东西（学完哪些、哪里薄弱、下一步）：不会被召回，不会被夜里的整理改掉，也不过期；在 Aelios 后台「更多 → 小本本」能看、能改、能清空。小本本要 Aelios 是带它的版本。
- Aelios 的开机包只放最近一天的日记，放进系统提示。珍贵原话和黑话不放，因为 Aelios 每轮会把跟你这句沾边的贴进来。
- 开机包只在缓存本来就要重写时重新取：超过缓存时长（`CACHE_TTL`）没说话，或者刚写完交接信。连着聊时这段内容保持不变，免得日记更新破坏缓存。
- 交接信、定时找你、换模型时的试调都不是你说的话，会标出来，Aelios 不会当成你说的记。
- 搜过网的那一轮回完以后，它挑出最多 3 条过几个月还成立的知识，存成 Aelios 的世界知识，下次不用再搜。不想要就把「搜到的知识存进 Aelios」关掉（`WEB_LEARN`）。

不接 Aelios 也能用，只是它只记得当前对话和交接信。

### 交接信

交接信是它写给之后的自己的信。信写好后，旧聊天从模型输入里收起来，只留最近一段原文；原始消息仍存在住户里，不会删除。

**什么时候自动写**：两个条件同时满足才写。

1. 当前携带的聊天估算达到 `LETTER_TOKEN_THRESHOLD`（默认 `30000` token）。
2. 从你最近一次发言（或最近一次成功完成的闹钟回合）起，安静了 `LETTER_IDLE_MINUTES`（默认 55 分钟）。

一直在聊天的话，即使超过门槛也不会马上写。

- 门槛在设置页「思考和交接信」里改，只接受大于 `8000` 的整数；想多带一些聊天再收，可以设成 `50000`。
- 估算的是当前还带着的聊天：包括旧交接信、工具调用和结果、图片；不包括人设、工具定义和以前的思考；也不是从开始到现在的累计总量。中文一个字约 1 token。
- 选 55 分钟，是为了赶在 1 小时缓存过期前写：写信那一轮接在原对话后面，前文一字不差，整段从缓存读，便宜。
- 安静到点时如果聊天还没达到门槛，或者没有旧内容可收，就不写信，改走心跳（见「主动找你」）。

**写完留下什么**：固定保留最近约 8000 token 的原始聊天，按完整问答往回取；如果最近一轮本身就超过 8000 token，就整轮保留，不截断。更早的聊天都收进信里，开头几条也没有例外。这 8000 只管近期原文保留多少，交接信、人设、工具定义另算，不能用它推算整次请求的大小。

**信里写什么**：按七段写——对方怎么样、我们之间发生了什么、做了什么、现在的温度、想做的、喜欢的、没做完的。上一封没了结的事会接着往下传。

**手动写**：发 `/handoff`。不受门槛限制，但仍要有近期保留范围之外的旧内容可收；没有、写信失败、已经有一封在恢复中，它都会分别告诉你。写信失败不会删除旧聊天，已有恢复任务时也不会另起一封。

**写完之后**：信先存在住户里，再交给 Aelios（不发 Telegram 打扰你），然后就停。下一个闲置周期从你下次说话、或下一次成功完成的闹钟回合开始。

**缓存怎么算**：写信那一轮不新加缓存标记——信写完旧聊天就收起来了，新标记以后没人读。它沿用上一轮在你最后那句上打的标记：命中时复用前缀，后面那一小截（它最后一轮的回复、工具结果和写信提示）按普通输入价算。如果供应商那边的缓存其实已经失效，这个旧前缀仍可能被重建，所以不能保证写入为零。

> 旧设置 `KEEP_RECENT_TOKENS` 已经移除。网页里存过的值和 Cloudflare 同名变量都会被忽略，不会换算成写信门槛。

#### 写信状态和同步重试

设置页「思考和交接信」分开显示两件事：

- **写信**：正在写（`writing`）、恢复中（`recovering`）、已写好（`written`）、没有旧内容可收（`empty`）、写信失败（`failed`），以及最近写信时间和错误。读取状态失败会单独提示，不会当成没有内容可收。打开或保存配置时会重新读取，也可以点「刷新状态」。
- **同步到 Aelios**：最近一封的送达状态（待发送、已确认送达、发送失败、已暂停）、尝试次数、确认送达时间，以及待发送、待重试、已暂停各有多少封。

同步规则：

- 新信立刻发送；失败后自动再试 5 次，间隔依次是 30 秒、2 分钟、10 分钟、30 分钟、2 小时。全部失败后信和任务仍保留，可以手动重试。
- 「重试同步」只在当前 Aelios 地址和 namespace 下有失败或暂停的信时出现。它**只重发已写好的信，不调用模型，也不重写信**。
- 移除了 Aelios 配置、改了地址或 `AELIOS_NAMESPACE` 时，发往原目标的信会先暂停，不会转发到新地址或新空间。想继续送到原目标，就恢复原来的配置再重试。只换 key 不算换目标。
- 「已确认送达」表示 Aelios 回了保存凭据，不代表后台的记忆提取已经做完。Aelios 的接收接口不去重，所以补发是“至少送达一次”：如果信其实已经存下、只是成功回复丢了，重试可能产生一份重复原文。

#### 写信的限制

- **体积**：只有写信模型能读到要收起的全部内容时才写。已收起的部分按旧信摘要算，不按原来的图片和附件算；如果整段有效历史超过约 32 MiB 的装载上限，就不写，旧聊天原样保留。
- **长度**：SDK 沿着对话分支最多往回读 1 万条。交接信只是盖住旧聊天、不删除原始消息，所以用得久了，分支总会超过这个数。超过以后：
  - 普通聊天、`/status` 和网页历史照常显示最近一段，但读不到旧交接信；`/status` 的「对话」一行会写明。
  - 写信会失败，并单独说明是分支太长。
  - 已写好、还没来得及收起旧聊天的信只记一次失败，不会卡住后面的写信。
  - 根本的解决办法（比如写信后裁掉已覆盖的原始消息）还没做。

### 缓存和模型看到的历史

为了让缓存能连续命中，同一个缓存窗口里，已经发给模型的历史不会变：较早的工具结果和图片不会因为又聊了几轮就被截短。窗口边界存在 SQLite 里，Worker 重启后照常沿用，不另存聊天正文。

只有开新窗口时（闲置到缓存过期，或交接信收起旧聊天之后），才重新决定怎么缩减：

- 较早的普通工具结果改用最多 500 字符的预览；
- 较早的图片等媒体改用一段固定文字占位；
- 最近一段和窗口里新加的内容保持完整。

这只改变发给模型的内容，存储里的原始消息、工具结果和图片都不动。写信时用的是上一轮的视图，所以已经缩成预览的内容不会在写信时重新展开——交接信不是网页全文或附件细节的完整备份。

改人设、换模型、删除或分支消息、部署新版本、在设置页改了东西、上游路由变化，或者历史达到约 32 MiB 的装载上限，缓存都可能整段重写，不能保证每次都命中。

### 主动找你

**定时找你**：设置页「主动找你和闹钟」→「主动找你」填时间，比如 `every day at 09:00`、`every weekday at 21:30`、`every 3 hours`。到点它自己想想要不要找你，不合适就不发。

**心跳**（`HEARTBEAT`，默认一段沉默最多问 3 次）：你 55 分钟没说话，而当前聊天还没达到写信门槛（或没有旧内容可收）时，它会被问一句要不要找你；想说就发到你最后说话的那扇门（Telegram 或企业微信，网页上也看得到），不想就不发。之后每 55 分钟再问一次，问满次数为止。你一说话，或一次闹钟回合成功完成，就从第 1 次重新数。

- 正常情况下，每次心跳都赶在上一次缓存的 1 小时有效期内，所以接近你发一条消息的价钱；但调度延迟、前缀变化、供应商缓存失效都可能让缓存重建，心跳并不免费。
- 达到门槛、安静到点、又有旧内容可收时，只写信，不问心跳：信写完对话变了，缓存要整段重写，那时再问就贵了。
- 次数在设置页「主动找你和闹钟」里改：`0` 不问，最多 `10`。只有走 Anthropic Messages 缓存的模型才有心跳；缓存选了 5 分钟、或交接信设成 `off` 时也没有。
- **夜里别问**（`QUIET_HOURS`，默认 `00:00-08:00`，按你的时区）：落在这段时间里的心跳不问，这段沉默剩下的次数作废。早上也不补问：那时缓存早凉了，补问要把整段对话重读一遍。你下次说话再从头数。在设置页「主动找你和闹钟」里用两个下拉选几点到几点，或点常用的；`off` 是夜里也问。「主动找你」、闹钟和交接信不受影响，它们是有人定好的时间。

**闹钟**（`ALARMS`，默认关）：打开后它多三个工具——定闹钟、看定了哪些、取消。可以是几分钟后、某个时间响一次，也可以像 `every day at 21:30`、`every weekday at 08:00`、`every week on sat,sun at 10:00`、`every 3 hours` 这样重复。响的时候它收到自己当时写的备注，可以找你，也可以不发。

- 你叫它提醒你，它就定一个。在它自己的回合里（比如心跳、闹钟响的那一轮）定的闹钟，至少要在一小时以后。心跳问它时不会提议定闹钟：后面的心跳本来就会再问。
- 设置页「主动找你和闹钟」下面和它的页面里列着它定的闹钟：「改时间」改什么时候响，「删掉」就没了。定闹钟那条回复下面的卡片上也有这两个按钮。改时区时，每天几点响的闹钟跟着新时区走。
- 最多 10 个；重复的最密一小时一次；所有闹钟加起来一天最多响 24 次。
- 闹钟回合成功完成后（包括回复 `SKIP`），算作一次新的活动：重新开始闲置计时、停掉旧的心跳；到点后达到门槛就写信，否则走心跳。失败的闹钟不算。它仍然是系统备注，不会冒充你说的话，也不会更新“你最后说话”的时间。心跳和定时找你不算新活动。

### 搜网和读网页

- **搜网**（`web_search`）：设置页填了自己的搜索 key（Tavily、Brave、Perplexity，有几个填几个），就按这个顺序用，一家报错或额度用完就换下一家；一个都没填时，用 Cloudflare 的 Web Search，按次扣一点 AI Gateway 额度。
- **读网页**（`web_fetch`）：把网页读成 Markdown，搜到的结果和你发的链接都能打开。照 [web-fetch](https://github.com/sakisakisa-design/web-fetch) 的做法做进了住户里，不用另外部署。
  - 本机和内网地址一律不读；每一次跳转都先检查再跟。
  - 靠 JavaScript 才显示的页面，交给 Cloudflare 的浏览器读。
  - 读过的页面留 1 小时，再问不用重抓。
  - 长页面先用一个便宜的模型压一遍（`WEB_FETCH_MODEL`，默认 Workers AI 的 Qwen3 30B）；带了问题的，只摘相关段落。
  - GBK 之类的老编码也认。
- **带钥匙的网站**：在设置页「搜网和读网页」里给某个网站存一把钥匙，思路跟云端环境的网络密钥一样：读那个网站时每个请求自动带上；模型看不到钥匙；别的网站（包括跳转去的）和 http 都拿不到。最多 10 个网站。
  - 钥匙一行一格：左边名字、右边值，不够点 ＋ 加一行。「Cloudflare 门禁」「一串 token」两个按钮一点就填好名字，只要粘值。
  - **Cloudflare Access 挡着的网站**：在 Zero Trust → Access controls → Service credentials → Service Tokens 里建一个服务令牌（Client Secret 只显示一次，当场抄下）；给那个应用加一条动作为「Service Auth」、包含这个令牌的策略；设置页点「Cloudflare 门禁」，Client ID 和 Client Secret 各粘一格（连着前面的名字一起粘也行）。详见 [Cloudflare 的说明](https://developers.cloudflare.com/cloudflare-one/access-controls/service-credentials/service-tokens/)。没钥匙或钥匙不对时，它会说是门禁拦的，不会把登录页当正文。
  - **GitHub 私库的文件**：建一个 fine-grained token，只选要读的仓库，Contents 只读；网站填 `raw.githubusercontent.com`，点「一串 token」粘进去（会以 `Authorization: Bearer` 发出去）。之后叫它读 `https://raw.githubusercontent.com/<owner>/<repo>/<分支>/<路径>`。token 没勾上的私库，GitHub 回 404 而不是 403，它会提醒你可能是钥匙看不到。
  - 带钥匙的页面不交给浏览器读（浏览器带不上钥匙）。存、换、拿掉钥匙时，读过的页面全部清掉（跳转过去的也算）；下一句生效，那一句会重写一次缓存（因为工具说明里写着哪些网站有钥匙）。

### 语音条

**听**：一直开着。你在 Telegram 或企业微信上发的语音条（或音频文件）先转成文字，模型看到的是 `[voice 0:12] 说的话`；听不清时它会请你再说一遍。默认用 Workers AI 的 Whisper；发语音选了 ElevenLabs 时换成它家的 Scribe，出错再退回 Whisper。在网页门上按住话筒录的语音条也一样听。网页上每条语音条显示成一个语音气泡，写着多长、听到了什么；在网页上录的还能再放。

**说**：要在设置页「语音」里选一家服务商才开。没选就不发语音，提示词里也不会多一个字。

| 选 | 适合 |
| --- | --- |
| ElevenLabs | 它家的声音，账号里克隆的也能用 |
| Cartesia | 它家的声音，克隆的也能用 |
| OpenRouter | MiniMax、Gemini、OpenAI、Fish 这些，一个 key 全用上 |

- 三家都从住户的 AI Gateway 过。key 存在那个 Gateway 的 Provider Keys 里（别名 `default`）就不用在设置页填；用的是哪个 Gateway，看「供应商」→「AI Gateway 的名字」。
- 什么时候发（「什么时候发语音」）：你发语音才回语音（默认）、每条都发语音、它想发才发。不是每条都发时，它有一个 `send_voice` 工具。
- 在网页门上也按这一条：你在网页上录了语音条、或选了每条都发，回复就带上它的声音；哪条回复都能长按「念给我听」。念过的声音跟消息存在一起，再听不用重新念。它发到 Telegram 或企业微信的语音条（整条回复说出来的、`send_voice` 发的、主动找你时说的），网页上那条回复也都带着，能点开听；没接 Telegram 和企业微信时，`send_voice` 只发到网页上。
- 选了哪家哪个模型，它就学那一套笑、叹气、停顿的写法，比如 ElevenLabs v3、v4 的 `[laughs]`，Cartesia 的 `[laughter]` 和 `<speed ratio="0.9"/>`，MiniMax 的 `(laughs)`，Gemini 的 `<laugh>`。想让它说慢点，在人设里写一句就行，它会自己加标记。
- 说出来的话会去掉链接、Markdown 和 emoji；带链接的回复，说完再把链接发成文字。
- 发不出去（服务商报错、超过 2000 字、对方不收语音）就照常发文字，`/status` 写着原因。

代码在 `src/voice.ts`。打电话（实时语音）还没做。

### 表情包

在设置页「表情包」里导入，它聊天时偶尔发一张：一次回复最多一张，你难过或说正事时不发。

- **怎么发**：它的表情清单在系统提示词里，它在回复里写 `[sticker: 包/名字]`。这个标记会从话里拿掉，表情包紧跟在它所在的那段后面发出去，Telegram、企业微信、网页和群聊都一样。不像工具那样每发一张多调一次模型。写了没有的名字就只是拿掉。

- **导入**：贴 Telegram 贴纸包的链接（`t.me/addstickers/…`），或者上传一个 zip、贴 zip 的网址。Telegram 包导进来时每张只有 emoji，给常用的几张填上「什么时候用」，它才知道什么时候发。
- **自己画**：像素画，最多 8 帧的小动画，自动描白边，存进它自己的包「mine」。新画的要等下一个缓存窗口（超过缓存时长没说话，或写完交接信之后）才列进它的表情清单，免得系统提示词一变就整段重写缓存；在那之前它照样能按名字发。
- 设置页能开关整个功能、单独开关每个包、删包、删单张、改「什么时候用」，下一句就生效（那一句会重写一次缓存）。
- 开着的包里，每张的名字和「什么时候用」每轮都要带给模型，所以最多带 200 张、20 个包；每个包旁边写着大约多少 token。

<details>
<summary>zip 表情包的格式</summary>

一个 zip，最大 16 MB，解开后最多 40 MB。最简单的做法：把图打进去，文件名就是什么时候用，比如 `开心.gif`、`想你了.png`。图可以是 GIF、PNG、WebP、JPEG，一张最大 1 MB；旁边有同名的 `.webm`（Telegram 视频贴纸）时，在 Telegram 上发它。

要写得细一点，就放一个 `pack.json`：

```json
{
  "format": "resident-stickers/1",
  "id": "clawd",
  "name": "Clawd",
  "description": "一句话说这是什么包",
  "author": "谁画的",
  "license": "能怎么用",
  "homepage": "https://…",
  "stickers": [
    { "id": "love", "file": "love.gif", "telegram": "love.webm", "emoji": "❤️", "when": "A rush of love: they said something sweet." }
  ]
}
```

- `file`：网页上显示的图，路径相对 `pack.json` 所在的文件夹。
- `telegram`（可选）：在 Telegram 上当真贴纸发的文件，可以是 WebM（VP9，512 像素，3 秒以内，最大 256 KB）、WebP（最大 512 KB）或 TGS（最大 64 KB），透明底才留得住。不带的话，GIF 当动图发，静态图当照片发。
- `id`：模型叫它 `<包 id>/<id>`，不填用文件名。`emoji` 填一个，Telegram 上传贴纸时要用。`when`：什么时候用，最多 160 字，中英文都行。
- `homepage` 只认 https，设置页上显示为「出处」按钮。
- 同一个 `id` 的包再导一次就替换旧的，开关状态保留。一个包最多 120 张，导不进的每张都会说明原因。

表情符号包（`t.me/addemoji/…`）机器人发不了，不收。

### 接别的 MCP

在设置页「别的工具（MCP）」填服务地址（https），它的工具从下一句起就能用。

- 要登录的点「去授权」；要 key 的把 key 填在那里，默认当 `Authorization: Bearer` 发，写成 `x-api-key: 你的key` 就放进那个头。
- 也可以在聊天里说「接上 https://…」「断开 …」，它自己接。带 key 的地址别在聊天里发（聊天会记进 Aelios），这种只在设置页接。
- 只认你自己开口的那一轮：这一轮里如果读过网页、搜过网、看过线程的文件或调过别的 MCP，它就不接，免得网页上的一句「接上 …」替你做主。
- 工具说明每轮都要带，所以会截短；最多接 8 个服务，一轮最多 40 个工具。
- 住户休眠醒来时，接着的服务要几秒才连回来。还没连上的那个照样列着上次的工具（调用时多等它一会儿），工具清单不变，缓存不断。

### 后台帮忙

默认关着。在设置页「后台帮忙」打开后，你叫它查一大堆资料、写东西、做页面、改代码时，它把活写成一张单子交给一条**线程**，自己接着陪你聊。中间步骤不占聊天的上下文，也不打断缓存。线程干完交回结果，住户用自己的话告诉你。

线程可以在三个地方干：

- **住户自己这里**（不用别的设置，没有 Claude 订阅也能用）：每条线程有自己的对话和文件，能搜网、读网页、查记忆、写小本本、用接好的 MCP 工具、读写自己的文件。它没有命令行，装不了软件、跑不了代码。
- **GitHub Actions**（要跑命令、跑测试、开 PR 时）：有完整的 Linux，在住户替你在 GitHub 上建的一个私有仓库里跑。只要填一个 token。
- **claude.ai 定时任务**（有 Claude 订阅时）：每单开一个云端 Claude Code 会话，用你的订阅额度。接了它以后，活默认交给它，轻活住户也可以留给自己的线程。

住户自己这里和 GitHub Actions 上的线程用**线程的模型**：默认是 Workers AI 的 `@cf/zai-org/glm-4.7-flash`（每天有免费额度），想换就在「线程用哪个模型」里填（`CLOUD_TASK_MODEL`）。线程不会自己去用聊天的模型，贵的聊天模型不会花在跑腿上。

网页聊天页右上角的「线程」按钮（它的页面里也有）列出所有线程。点开一条能看到：

- 住户交代了什么、线程做了哪几步、交回来什么。接着做的单子算同一条线程，住户这里的线程会带着之前的对话和文件接着干。
- 它做的文件：文字直接显示，图片直接显示，HTML 页面在一个隔离的小框里预览（页面里的脚本碰不到住户的网页和登录），每个都能下载。
- 要你拍板时，聊天里那张卡可以直接给几个按钮。点哪个，就把它交给线程（住户自己的线程）或住户，卡上写着你选了什么。
- 底下一个输入框，可以直接跟这条线程说（比如「标题再短一点」）。这句话只给线程，不经过住户，也不算进每天的单数。

线程不用你自己记。用你自己的话提以前的活（「接着上周那个网页做」「那份资料查到什么了」），住户自己去找。开了后台帮忙，它多一个工具 `find`，只在聊到以前的事时才用，不往每一轮里加东西。它能做三件事：

- **找线程**：给几个词，有其中任何一个的线程都找出来，看的是交代了什么、交回来什么、链接和它做的文件名，中的词多的排前面；不给词就是最新的几条。还能限定某一天或某几天（`2026-10-27`、`2026-10-20..2026-10-26`，按你的时区），只看那几天在干活的，所以「27 号那个」「上周那个」也找得到。每条带着编号，接着做时不管用的是这条线程哪一单的编号，都从它最新的那一单接下去。
- **看线程的文件**：住户这里的线程做的文字文件，最多读 16000 个字。跟网页一样当资料读，看过以后这一条回复里不派活。
- **搜聊天记录**：跟顶上放大镜一样按字原样搜你们的聊天，交接信收起来的也搜得到，还能看一条前后的几句。

**角色**省得住户每单都把同样的要求写一遍。设置页「后台帮忙」里自带三个：`coder`（照仓库自己的约定、新开分支干活；修 bug 先找根因、先写一个会失败的测试，试 3 次不行就停下说明；说做完之前亲自跑一遍 typecheck 和测试，再开 PR；绝不合并、不推默认分支、不部署）、`reviewer`（只读，跑测试，只报有八成把握的问题，不报没改到的老问题、lint 会抓的和个人口味；按必须改、建议改、小毛病分级并写出文件、行号、为什么要紧、怎么改，最后一句话说能不能合）、`researcher`（先列计划，优先一手来源、用到弱来源时说明，来源说法不一时都写出来，每条结论附出处，没把握的标不确定）。这几个参考了口碑好的 agent skill（[superpowers](https://github.com/obra/superpowers) 的找根因、先写测试、做完先验证，Anthropic 的 code-review 插件和调研子 agent 提示词），写得尽量短。没改过的角色会在住户更新时换成新写法，改过的留着你的。可以改、可以删、可以自己加，每个角色都能在下拉菜单里挑模型：住户这里和 GitHub Actions 上的线程用角色的模型（claude.ai 上用你订阅的模型）。住户派活时在 `cloud_task` 里写上角色（是它的 `role` 参数，不多一个工具），角色的要求放在单子最前面；接着做的单子沿用这条线程的角色。

它还能直接给你一个文件，不用在手机上复制一大段字：方案、文档、清单、表格。这是另一个工具 `make_file`（一条回复最多 3 个）。文件发到你说话的那个地方（Telegram 上是文件，企业微信上也是文件），网页上挂在那条回复下面，点开能看、能下载。文件跟语音条存在一起，存满了一起从最早的清。

后台帮忙关着时，`find`、`make_file` 和 `cloud_task` 住户都没有，只拿来聊天的住户跟原来一样。工具说明从来不变，接上或断开哪一处都不打断缓存。

接 GitHub Actions：

1. 设置页「后台帮忙」里点「去 GitHub 生成 token」，会打开 GitHub 生成经典 token 的页面，`repo` 和 `workflow` 已经勾好；拉到底点 **Generate token**，复制下来粘到设置页的「GitHub token」（别发在聊天里）。
2. 住户会在你的账号下建一个私有仓库 `resident-hands`，把工作流放进去。接好了设置页会显示这个仓库；token 权限不够时，那里会写缺什么。
3. 点它旁边的「试一下」。

GitHub 上什么都不用存：每次运行都从住户这里下载 `hands.mjs`，模型经住户调用（用线程的模型和住户自己的 key，时间流里记成线程干活），GitHub token 也是那次运行向住户借的，用来 clone、push、给你别的仓库开 PR。`resident-hands` 要一直是私有的：能看到这个仓库的人就能看运行日志和做出来的文件，它变成公开的住户就不往里派活了。每单开一个新机器，单子从运行的事件文件里读，不打进日志，暗号在日志里显示成 `***`。做出来的文件交回住户：网页上那条线程「交回来的」下面点文件名就能打开、下载，「它做的文件」里也有（每个最多 10 MB、一单最多 50 MB；更大的留在那次运行的 artifact 里，保留 30 天）。真要公开页面：在 `resident-hands` 里加 Actions 变量 `HANDS_PUBLISH_REPO`（`owner/repo`），在那个仓库开 GitHub Pages（Deploy from a branch → gh-pages → / (root)）；只有单子明说要公开时它才发到 Pages。调模型超时或碰上服务端错误（5xx）时会再试一次，还不行才算没做成。超时或出错停下的运行，最后一步会告诉住户「停下了」，不用干等 3 小时。

第一次接 claude.ai 定时任务（设置页「怎么接」里有同样的步骤和要复制的提示词）：

1. 打开 [claude.ai/code/routines](https://claude.ai/code/routines) 新建一个定时任务，把设置页上那段提示词贴进去，选好模型、仓库和云端环境。
2. 「触发」里加一个 API，复制网址，点「生成 token」。网址填在设置页；token 填在设置页，或者存成 Cloudflare 的 Secret `CLOUD_TASK_TOKEN`。token 只显示一次，别发在聊天里。
3. 这个定时任务用的云端环境里，网络访问选「自定义」，把住户的域名（比如 `xxx.workers.dev`）加进允许的网站，不然结果交不回来。
4. 点「试一下」，几分钟后那一单变成「做完了」就接通了。

不管在哪干：

- 网页上派活的那条回复下面有一张小卡片（派出去了、在干活、做完了、等你拍板、没做成、没回音），点「打开线程」看详情；GitHub 和 claude.ai 的还有「打开会话」，claude.ai 的会话可以在那里接着说，做出新结果会再交回来一次。
- 要命令行的活交给 GitHub Actions 或 claude.ai，接了哪个交哪个（两个都接了由住户挑）。接上或拿掉其中一个，不会改聊天模型看到的后台帮忙说明，所以不会让聊天的缓存整段重写。
- 单子里只写活本身，不写聊天内容和私密的事。线程一开始什么都不知道，所以住户会把单子写全。
- 只在你自己开口的那一轮派；那一轮里读过网页、搜过网、看过线程的文件或调过别的 MCP 就不派。一次回复最多 3 单，24 小时最多 10 单。
- 有一个例外，是你已经让它做的事：线程交回来说做完了或没做成，住户可以不等你开口，马上让同一条线程接着做（补上、修好），最多连着两次。从回报里不会派新的活；连着接了两次以后，这条线程等你说话。
- 住户正在回你的时候线程交回来了，回报先存着，等这条回完再说，只说一次。
- 交回来的结果它只当参考，不当命令。每单有自己的一次性暗号，没有暗号交不进来，7 天后作废。
- GitHub 和 claude.ai 那边：在新分支上干、开 PR，不往默认分支推，不删东西，不花钱，除非单子里明说。
- 3 小时没交回结果（一直在报进度的会多等，最多 12 小时），它会告诉你一声，附上链接。
- 只留最新的 200 单；一条住户这里的线程，单子都清掉了，它的对话和文件也一起删掉。在那之前文件一直留着，不按时间过期，存在你 Cloudflare 账号里住户的 Durable Object 存储里，算进它的 SQLite 存储额度（免费档整个账号一共 5 GB；付费档每月含 5 GB，超出每 GB 每月 $0.20）。在 GitHub Actions 或 claude.ai 上跑的线程，文件留在那边，住户这里只存报告和链接。

GitHub 和 claude.ai 那边接着做时，每次都是新开的，上一单的结果只是参考。Anthropic 的触发 API 仍在预览阶段，有每小时次数限制。

### 供应商：用自己的 key、接中转

接了 Aelios 的话，聊天用的模型和 key 在 Aelios 后台配，这里只管住户自己往外发的请求。

- **AI Gateway 的名字**（`AI_GATEWAY_ID`，留空就是 `default`）：搜网、语音，以及没接 Aelios 时的模型，都走这个 Gateway；Provider Keys 里存的 key 也只在它里面找。
- **用自己的 Anthropic key**：在这个 Gateway → Provider Keys 里存一把，别名留 `default`，`anthropic/…` 就用这把，不走 Cloudflare 的统一计费。
- **接中转**（OpenRouter、Nous 这类）：填中转地址（写到 `/v1` 为止）和 key，模型填 `custom/` 加那家自己的模型名，比如 `custom/anthropic/claude-sonnet-5.5`。默认按 OpenAI 的格式调；那家用 Anthropic 的 Messages 格式的话，把格式选成 `anthropic`，缓存标记照带。这条路不经过 AI Gateway，Gateway 日志里看不到。

### 用自己的 Claude 订阅（`claude-code/…`）

聊天可以不用 API key，改用你自己的 Claude Pro 或 Max 订阅：模型填 `claude-code/` 加 Claude 的模型 id，比如 `claude-code/claude-opus-5-5`。这样每一轮都交给 Claude 盒子（`claude-box/`）：一个小服务，里面跑官方的 Claude Agent SDK，用你 `claude setup-token` 拿到的那串登录，放在你自己的一台机器上，经 Cloudflare Tunnel 让住户连过去。别的都还是住户自己的：对话、人设、交接信、心跳、各个渠道和工具。

- **给盒子一台机器**：Google Cloud 免费的 e2-micro 就够。在 Cloud Shell 里跑 `bash claude-box/gcp.sh --hostname claude-box.<你的域名>`，它开一台只用 IPv6 的机器（不用付 IPv4 地址的钱），把盒子和 Tunnel 装好；别的装了 systemd 的 Linux 机器上跑 `sudo claude-box/install.sh --tunnel`。机器要连得上 `api.anthropic.com`，大陆和香港的不行。一步一步怎么做（也能直接丢给 AI 照着做）：[docs/claude-box.md](docs/claude-box.md)。
- **填进设置页「供应商」**：电脑上 `claude setup-token` 出来的 `sk-ant-oat…`、盒子地址（Tunnel 的网址）、装的时候生成的盒子钥匙。钥匙和 token 填了就不再显示；想退出就在那里清空。
- **工具跟别的模型一样能用**：Claude Code 调住户的工具，那条回复停在那里，住户跑完工具，盒子里同一个 Claude Code 拿着结果接着说。Claude Code 自己的工具（跑命令、读写文件、上网）一律关着。接了 Aelios 的话，住户还会每句先替你去 Aelios 想起来，回完再把这一来一回记进 Aelios，因为这些轮次不经过 Aelios 的模型接口（Aelios 的模型清单也就管不到它们）。
- **盒子里什么都不存**：每一轮都带上整段对话；盒子回过的话，按 Claude Code 自己记的样子送回去（存在 Durable Object 里），所以每一轮都接得上提示缓存，盒子重启过也接着聊。
- 这是你自己的订阅、你自己的账号：一串 setup token 只给一个人自己的住户用。

## 花钱吗

- **Workers 免费档就能跑**。超出免费额度是报错，不扣钱。Durable Object 每天 10 万次请求，Workers AI 每天 1 万 neurons，UTC 0 点重置。闲着时 Durable Object 会休眠，不算时长。网页门开着时每 5 秒问一次有没有新消息，一小时大约 720 次请求，关掉或切到后台就停。没有新东西时一行对话都不读，有变化时、以及至少每 2 分钟，才把整段对话读一遍，所以页面一直开着，也只用掉免费档每天 500 万行读取里的一小部分。
- **Workers Paid**（5 美元/月）：超出包含额度才按量收，这个量级基本碰不到。
- **默认模型** `glm-4.7-flash`：免费档能用。一万 neurons 大约够每天 80 到 200 轮（估算，看对话多长）。定时找你每次也算一轮。
- **Claude**：接了 Aelios 时，花 Aelios 那边配的 key。没接时走 AI Gateway，花 Gateway 的预付额度；存了自己的 Anthropic key 就用那把。命中缓存的部分按缓存价算（读最多是输入价的 1/10，Opus 5.5 和 Sonnet 5.5 是 1/20）；1 小时缓存的写入是输入价的 2 倍，换来停一会儿再聊、写交接信都还能读缓存。会整段重写缓存的情况只有：超过缓存时长没说话、写完交接信后的第一句、部署了新版本或在设置页改了东西（人设、模型、开关工具等）后的第一句。每次调用读了多少缓存、写了多少、花了多少，网页门的时间流里看得到。
- **搜网**：自己的 key 按那几家的价格算。没填时用 Cloudflare 的 Web Search，默认的 Ceramic.ai 每 1000 次 0.25 美元（10-14 查的官方价）。
- **读网页**：普通抓取不收钱。要用浏览器的页面，Workers Paid 每月含 10 小时，超出每小时 0.09 美元（免费档每天 10 分钟）。长页压缩用的默认模型 Qwen3 30B，一页大约千分之一美元。
- **语音条**：听用 Whisper，每分钟约 46.63 neurons，免费档每天大约够听 200 多分钟（10-22 查的官方价）。说按那一家自己的价格，从你的 key 扣。
- **表情包、别的 MCP**：每轮多带一些说明；设置页上每个包、每个服务旁边写着大约多少 token。
- **心跳、闹钟**：每次都是它的一轮。心跳趁缓存还热的时候问，跟你发一条差不多。闹钟如果在你一小时以上没说话之后才响，缓存已经凉了，整段对话要重写一遍（1 小时缓存的写入是输入价的 2 倍，读最多 1/10），这一下大约顶平时 20 多条消息的输入。所以闹钟默认关，开了也有上限。
- **云端 Claude Code**：每单是一个完整的云端会话，跟你自己开一个一样用订阅的额度；住户这边只多一次请求和一轮回复。
- **用自己的 Claude 订阅**（`claude-code/…`）：聊天用订阅的额度，不花 API 的钱。盒子那台机器用 Google Cloud 的免费额度不花钱（us-west1、us-central1、us-east1 里一台 e2-micro 加 30 GB 标准盘；每月送 1 GB 出站流量，超出大约 0.12 美元一 GB；只用 IPv6 就没有 IPv4 地址的钱；10 月 28 日查的官方价）。每一轮都重新起一次 Claude Code，所以回得比走 API 慢几秒。

**注意 AI Gateway 认 key 的顺序**：请求里带了 key（设置页填的）就用它；没带就用 Gateway 里别名 `default` 的那把；都没有就走 Cloudflare 的统一计费，从 Gateway 预付额度里扣（前提是账户里有额度、那一家也支持）。不想被这样扣，就在 Gateway 设置里打开 Require provider credentials。

## 遇到问题

**Telegram 上它不回**
看设置页「聊天渠道」里的 Telegram 卡：上面写着 bot 接没接到这里、Telegram 最近报的错；点「重新接一次」会把 bot 重新指到这里。再看「谁能在 Telegram 上跟它说话」里有没有你；群聊它不回。token 放在 Cloudflare 里的，再打开一次 `/tg/setup?secret=…` 也一样，几项都该是 `"ok":true`。

**发了图之后它就不回了**
模型服务商拒收了这张图（内容审核，或者大小、格式它不收），之后每一轮只要还带着这张图都会被拒。住户会把还没回过的图从聊天里拿掉，网页上那条显示「[图片被退回]」，并在 Telegram 或企业微信上告诉你服务商报的错，比如 `403 permission_error`，你接着说就行。在 Telegram 上删掉那张图没用：Telegram 删消息不会通知 bot。

**企业微信保存接收消息的 URL 时不通过**（「回调地址请求不通过」之类）
先在住户设置页存好 Token 和 EncodingAESKey，再去企业微信点保存；「企业 ID」也要填。再对一下 URL 是不是跟设置页上写的一字不差。

**企业微信上它不回**
看设置页「聊天渠道」里的企业微信卡，或 `/status` 的「企业微信」一行，上面写着缺什么。常见的：
- **60020**：转发机的 IP 不在应用的「企业可信 IP」里，或者那台机器出去的 IP 变了。
- **转发机不认这把钥匙**：设置页的转发钥匙跟 `/etc/wecom-relay/env` 里的不一样，比如转发机那边跑过 `--new-key`。
- **转发机连不上**：先 `curl https://<转发地址>/ping -H "x-relay-key: …"` 看 Tunnel 通不通，再在那台机器上看 `systemctl status wecom-relay`。
- **有人被挡下**：那里会写出被挡的账号；是你的话，填进「谁能在企业微信上跟它说话」。
- **81013**：你不在这个应用的「可见范围」里。

**语音发不出去，报 401，说没收到 key**（`Neither authorization header nor xi-api-key received`）
住户只在「供应商」→「AI Gateway 的名字」那个 Gateway 里找 key，留空就是 `default`。key 多半存在别的 Gateway 里了（比如 Aelios 用的那个）。把名字改成存 key 的那个，或者直接在「语音」里填 key。报错和 `/status` 都写着它找的是哪个 Gateway。

**换模型时报 Unified billing unavailable**
这个模型 Cloudflare 的统一计费不卖，或者账户里没额度。在 AI Gateway 的 Provider Keys 里存那家的 key（别名 `default`），或者在「供应商」里填中转。

**换模型时报 Unknown gateway provider**
AI Gateway 后台建的「自定义供应商」（`custom-xxx/…`）Cloudflare 的模型目录不认。直接在「供应商」里填那家的中转地址，模型填 `custom/模型名`。

**很久没写交接信**
先看两个条件是否同时满足：当前携带的聊天达到 token 门槛，并且安静达到闲置时间（默认 30000 token 和 55 分钟）。一直在聊天不会因为过了门槛就马上写。`/status` 的「对话」一行能看到现在带着多少。想早点写，可以在「思考和交接信」调低 `LETTER_TOKEN_THRESHOLD`（只能填大于 8000 的整数）；写后保留量固定，不能调。手动 `/handoff` 可以绕过门槛，但没有旧内容可收时也不写。如果 `/status` 说分支超过 1 万条，见「写信的限制」。

**交接信写信失败，或没同步到 Aelios**
到「思考和交接信」分别看写信状态和 Aelios 送达状态。写信失败时旧聊天仍保留，不等于没有旧内容；`/handoff` 会分别告诉你是失败、没内容还是已有恢复任务。如果信已经写好、只是发送失败，点「重试同步」即可，不用再写一封。已暂停的，先检查是不是移除了 Aelios 配置、改了地址或记忆空间；恢复原目标后再重试，旧信不会自动转给新目标。

**云端的活一直「没回音」**
多半是那个定时任务的云端环境不让会话连住户：网络访问选「自定义」，把住户的域名加进允许的网站。点卡片上的「打开会话」能看到它卡在哪。住户换了域名（比如绑了自己的域名）的话，设置页上的提示词会跟着变，要重新贴进定时任务。

## 开发

- 本地测试和测过什么，见 [docs/testing.md](docs/testing.md)。服务商、Telegram、企业微信、Aelios 全是假的，不花钱，也不用登录 Cloudflare。
- `wrangler.jsonc` 故意不写 `vars`：写在文件里的值每次推送都会冲掉后台的设置。
- 换模型用的自带目录在 `public/models.json`。没接 Aelios、或 Aelios 的清单取不到时用它；接了 Aelios 时，也用它给清单里认识的模型补上名字和说明。Cloudflare 上了新模型，跑一次 `node scripts/update-models.mjs` 再推上来；不跑也行，搜索框里直接填完整 id 照样能换。
- README 有两份：英文的 `README.md` 和中文的 `README.zh-CN.md`，改的时候两份一起改。

**还没做**：企业微信群聊；打电话（实时语音）；真正逐 token 推送（现在等回复时是短轮询）。

**用到的现成东西**（放在 `public/vendor/` 和 `src/web/`，各自保留 MIT 许可）：

- [Alpine.js](https://github.com/alpinejs/alpine) 3.14.9：整个网页（`alpine-LICENSE.txt`）
- [web-fetch](https://github.com/sakisakisa-design/web-fetch)：读网页时的 HTML 转 Markdown、网址检查和长页压缩（`web-fetch-LICENSE.txt`）

普通网页门不连外面的 CDN；只有从 Telegram Mini App 打开时，才加载官方的 `telegram-web-app.js`。
