# 在 DSH 中使用 Resident 与本机帮手

这是原生 DSH 集成的开发版说明。[独立插件源码](https://github.com/Aelios-project/dsh-plugin-aelios-resident)目前为组织私有仓库，包名为 `@aelios/dsh-resident`，当前开发版本为 `0.2.1`；源码目录名为 `dsh-plugin-aelios-resident`。它不包含在 Resident Worker 的部署产物中，也尚未发布到公开 npm。

## 平时看到什么

进入 DSH 的「Aelios 住民」面板，看到的是 Resident 原有的住户、聊天、线程和设置界面。网页、Telegram、企业微信和这里共用同一个住户的云端主对话。人格、交接信、长期记忆入口仍由 Resident 和原来的 Aelios 接入管理，DSH 不接管它们，也不把本机助手的整段工作日志灌回主对话。

需要本地帮助时，Resident 通过原有 `cloud_task` 入口派活。设备领取已排队任务后，插件创建独立的原生 DSH 会话处理，默认留在后台。主对话只显示任务卡片、必要进度和结果，任务更新不会自动把执行会话切到台前。

点卡片的「查看 DSH 执行过程」，才打开普通 DSH 会话界面。这里可以查看任务输入、模型回复和工具调用；会话仍受本机帮手的只读能力限制。点击「回到住民」返回原界面，关闭或收起执行视图不代表停止任务。当前不把导航按钮当作取消按钮。

ACP 不在这一版的执行链路中；这里用的是 DSH 自身的会话与模型能力。以后是否扩展其他 Agent，再根据实际需要设计。

## 开始使用

1. 准备已有的 Resident 站点。云端须包含本次桌面设备与任务 API 代码；单独安装插件不会自动升级 Worker。代码合入与生产部署仍须分别按项目流程执行，本说明不代表已经部署。
2. 在 DSH 插件管理器中安装、启用独立插件的本地源码目录。当前开发环境已安装时，刷新 DSH 后从侧栏或「更多」进入「Aelios 住民」。
3. 在插件连接页填写 Resident 的 HTTPS 根地址和网页钥匙 `WEB_KEY`。不要把钥匙发进对话或写入仓库；它由 DSH Host 凭据服务保存。原网页界面的隔离框架不接收真实钥匙。
4. 先在 Resident 原版设置中开启「后台帮忙」。再打开插件外层的「连接与本机帮手」，确认当前住户，点击「选择工作区」，选择需要它读取的文件夹，再点击「开启只读帮手」。这是可信 DSH 界面上的本机授权步骤，聊天消息和嵌入网页不能替代它。
5. 在 Resident 主对话明确交代一个需要读取该工作区的小任务。设备在线且任务可领取时，它在后台执行；需要查看细节时再点任务卡片。
6. 不再需要时，在同一设置中停用帮手或撤销设备。撤销后不再允许该设备领取任务、续租或提交有效任务更新；断开插件不会删除云端聊天、住户或 Aelios 身份。

云端代码尚未升级时，已有网页聊天接口仍可使用，但开启本机帮手会提示缺少对应接口。不要把这个提示当成已有设备已成功注册。

## 工作区、设备与住户的边界

首版每个住户支持一个已注册设备。网页连接、住户、设备和工作区授权共同约束任务；切换连接或住户不会把先前的文件权限自动带过去。工作区真实路径留在本机，云端只需知道不含敏感路径的标识和能力摘要。设备使用独立凭据，不把网页钥匙当作常驻任务领取令牌。

本机帮手当前只能列出和读取明确选择的工作区，不能写入、删除、移动文件、执行 Shell、安装软件、推送 Git 或再派生其他助手。普通 DSH 会话入口不代表给它换成了任意本机权限。机密文件、浏览器 Cookie、系统钥匙串和 API Key 不属于可供任务读取的背景资料。

Resident 原有执行值 `local` 仍指 Cloudflare 上的 Think 线程，`linux` 仍是 GitHub Actions，`external` 仍是原来的云端 Claude Code 路径。新增的 `desktop` 才是本机 DSH，未安装插件的用户继续使用原有云端后端。

## 断线与结果

云端主对话不依赖电脑常驻。电脑睡眠或 DSH 关闭后，手机和其他渠道仍可聊天，但本机任务不能据此视为已经执行或已经停止。

设备通过租约领取任务，并以带任务身份的事件回报结果。网络恢复只重传尚未确认的事件，不应直接重放已执行的本机任务。领取后 5 分钟没开始、或开始后失联超过 5 分钟（比如电脑睡着了），任务进入 `unknown`：不会自动重跑，也不挡这台设备领后面的任务。先在原设备看实际 DSH 会话，再决定让住户接着做还是新建任务；之后迟到的结果仍会收下。本版不承诺自动无损续跑，也不会因超时自动重新执行。

主对话的最终汇报沿用 Resident 的任务回报路径。本机原始工具日志留在执行会话，回传的是必要状态和结果摘要。

## 当前限制

- 原界面在没有同源权限的隔离 iframe 中运行。录音和系统 Push 通知请使用外层「完整网页」；嵌入页面不注册 Service Worker，也不读取或保存真实网页钥匙。
- 外部链接通过父页面确认后提供的外链按钮打开。沙箱内原有弹窗或新窗口行为可能受限，不能把无反应当作操作已经完成；需要时到完整网页继续。
- 首版为单设备、单个已选工作区的只读帮手。需要改文件或运行命令的任务不属于已交付能力。
- 查看执行过程是主动导航，返回 Resident 不等于取消；`unknown` 状态须人工核对，不能直接按自动重试处理。
- 插件已加载或 Host 工具可调用，不等于界面、真实模型、本机文件读取与跨端结果回报全部完成端到端验收。实际验收需在目标 DSH 版本和自己的测试住户上分别确认；本次代码变更不代表生产部署或 PR 已合并。

## 开发验证

在 Resident 仓库使用 Node.js 22 或以上版本，按项目要求安装依赖后运行：

```sh
npm run typecheck
node --test test/desktop-ui.mjs test/desktop-devices.mjs
```

完整本地 HTTP 链路另用 `test/desktop-worker.mjs`。按测试指南启动隔离的假服务与全新状态的本地 Worker 后，运行 `TEST_BASE_URL=http://127.0.0.1:8787 node test/desktop-worker.mjs`。测试只接受本机 HTTP 地址，使用合成设备凭据和脚本模型，检查单次领取、回报去重、最新任务映射、住户隔离与撤销；会留下合成住户历史供检查。它不创建或执行真实 DSH 模型会话。

前端测试包含无 DOM 依赖的桥接契约和明确标注的源码检查；设备测试使用本地 SQLite、合成凭据与离线路由契约。它们不要求真实云端密钥，也不等于浏览器端到端测试。

独立插件目录内运行 `npm test`，验证代理边界、原生任务桥接、权限和恢复等契约。同步原始前端资源使用该插件的 `npm run sync-ui`；运行前按插件说明确认 Resident 源码路径，避免发布陈旧的界面副本。真实页面检查、原生会话打开与返回、只读授权、撤销和失联状态还需单独验收，不把测试数量当作完整体验证明。
